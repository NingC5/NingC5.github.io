Git 是一个开源的分布式版本控制系统，被广泛使用。

  • 常用功能：仓库管理、文件管理、分支管理、标签管理、远程操作
  • 功能指令：add、commit、log、branch、tag、remote、status

Git 是分布式版本控制系统，可对任何类型的文件进行版本控制。特别是文本文件，Git 能够查看其内容差异。

Git 概念与命令

在提供的上下文中，’hunk’指的是Git在比较文件差异时识别出的更改块。Git将这个hunk视为从特定行开始，连续覆盖或影响了接下来的若干行。实际显示的行数可能与Git计算的行数不同，因为Git的计数方式包括了潜在的行号推进区。

  • Working Directory: 工作区
  • Staging area: 暂存区
  • .git directory(Repository): 仓库区

TIP: working tree 和 working directory 都指工作区（树），不同版本采用不同称谓，中译同理。

命令

git init 初始化仓库

在当前目录执行该命令以初始化仓库，即在当前目录下创建 .git 子目录。

git add 向暂存区添加文件

git commit 提交，记录

git status 查看仓库的状态

git diff 查看更改前后的差异

  • git diff ，查看工作区与暂存区的差异，即未暂存的改动
  • git diff --staged ，--staged 同 --cached ，查看暂存区与最新提交的差异，即已暂存的改动
  • git diff HEAD ，查看工作区与最新提交的差异

注意，git diff 本身只显示尚未暂存的改动，而非自上次提交以来所做的所有改动。

ex: 若修改后未暂存，git diff 显示的是工作区与最新提交的差异。若修改后已暂存，git diff 什么都不显示。

GitHub Desktop 的安装

Git 自带 GUI 界面，但其过于简陋，推荐使用 GitHub Desktop（众多 GUI Clients 中的一种）。

  1. 仓库操作：new & remove
  2. 文件操作：增改删都需要提交
    1. 版本号：由40个16进制的数字组成的版本号，又称为提交码，可以根据版本号找到文件位置
    2. 为了避免文件的损坏和丢失，每次操作都需要提交到版本库。
  3. 分支操作：分支&合并，合并时文件冲突的处理
    1. 分支操作等同于创建仓库副本，形成分支版本库。然后针对分支进行提交，最后将分支版本库合并到主版本库。
  4. 标签功能：每次提交都可以添加描述性文字，但合并是工具自动完成的，通过标签功能为每次合并添加描述性文字。
  5. 通过 GitHub Desktop 进行本地仓库与远程仓库（Github|gitee）的交互

  • README：一些描述信息

  • git比对功能只针对文本文件
